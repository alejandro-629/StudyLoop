# Local setup

StudyLoop runs locally on a Laravel Sail-compatible Docker Compose stack. You need **Docker with Compose v2**, `curl` and a free port 80 (or set `APP_PORT`). PHP, Composer and Node.js are not needed on the host: they run inside containers.

## One command

```bash
scripts/setup.sh
```

The script is safe to re-run. It:

1. copies `.env.example` to `.env` (once) and maps the container user to your host user (`WWWUSER`/`WWWGROUP`);
2. installs Composer dependencies with a throwaway PHP 8.4 container if `vendor/` is missing;
3. builds and starts the services and waits for MySQL and Redis to be healthy;
4. generates `APP_KEY` if it is empty;
5. runs migrations and the seeder;
6. installs npm packages and builds the Vite assets;
7. checks `GET /health` until it answers.

| Service | Purpose | Local URL / port |
|---|---|---|
| `laravel.test` | Laravel app (PHP 8.4) and Vite dev server | http://localhost, Vite on 5173 |
| `horizon` | Queue worker supervised by Horizon | dashboard at http://localhost/horizon (local env only) |
| `mysql` | MySQL 8, `utf8mb4`; also creates a `testing` database | 3306 |
| `redis` | Cache, sessions and queues | 6379 |
| `mailpit` | Catches outgoing mail | SMTP 1025, UI http://localhost:8025 |

## Everyday commands

```bash
./vendor/bin/sail up -d            # start
./vendor/bin/sail down             # stop (data volumes are kept)
./vendor/bin/sail npm run dev      # Vite with hot reload
./vendor/bin/sail artisan migrate:fresh --seed   # reset the database
```

## Quality checks

These are the same checks CI runs:

```bash
./vendor/bin/sail composer lint      # Pint, no changes allowed
./vendor/bin/sail composer analyse   # Larastan (level 6, empty baseline)
./vendor/bin/sail composer test      # Pest: Unit, Feature and Scheduler suites
./vendor/bin/sail npm run build      # Vite production build
```

The scheduler package can also be tested on its own, without Laravel:

```bash
cd packages/scheduler && composer install && vendor/bin/pest
```

Tests use SQLite in memory and array cache/session/queue drivers (see `phpunit.xml`), so they need neither MySQL nor Redis. CI additionally runs every migration up, down and up again against MySQL 8.

## Environment variables

All variables live in `.env` (never committed); `.env.example` has working defaults for the Compose stack.

| Variable | Default | Notes |
|---|---|---|
| `APP_KEY` | empty | Generated by the setup script. |
| `APP_URL` | `http://localhost` | Change together with `APP_PORT`. |
| `APP_TIMEZONE` | `UTC` | Timestamps are stored in UTC; learners' study days use their own timezone. |
| `DB_HOST` / `DB_PORT` | `mysql` / `3306` | Use `127.0.0.1` when running PHP on the host. |
| `DB_DATABASE` / `DB_USERNAME` / `DB_PASSWORD` | `studyloop` / `sail` / `password` | Local-only credentials. |
| `REDIS_HOST` / `REDIS_PORT` | `redis` / `6379` | Used by cache, sessions and queues. |
| `CACHE_STORE`, `SESSION_DRIVER`, `QUEUE_CONNECTION` | `redis` | Horizon processes the `redis` queue. |
| `MAIL_HOST` / `MAIL_PORT` | `mailpit` / `1025` | Mail is caught by Mailpit, never delivered. |
| `APP_PORT`, `VITE_PORT`, `FORWARD_*_PORT` | `80`, `5173`, … | Host ports; change them if something else uses the default. |
| `WWWUSER` / `WWWGROUP` | `1000` | Set by the setup script to your `id -u` / `id -g`. |

## Demo accounts

There are no demo accounts yet: sign-in arrives together with organizations, cohorts and invitations. When it does, the seeder will create synthetic accounts for each role (org admin, instructor, TA and learner) and they will be listed here. All demo data is synthetic.

## Troubleshooting

- **Port 80 or 3306 already in use:** set `APP_PORT` / `FORWARD_DB_PORT` in `.env` and run `./vendor/bin/sail up -d` again.
- **Permission errors in `storage/`:** check that `WWWUSER`/`WWWGROUP` in `.env` match `id -u` / `id -g`, then rebuild with `./vendor/bin/sail build --no-cache`.
- **`/health` returns 503:** the response says which dependency failed (`database` or `cache`); details are in `storage/logs/laravel.log`.
